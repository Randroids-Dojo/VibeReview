# AGENTS.md

## Project

VibeReview is a native macOS SwiftUI/AppKit app for capturing browser game review feedback. It records screenshots, notes, tags, and browser state into review sessions under the selected game project's docs.

## Requirements

- macOS with Xcode installed.
- XcodeGen available on `PATH`.
- Network access may be needed the first time Swift Package Manager resolves `KeyboardShortcuts`.

## Build

Generate the Xcode project and build the app:

```bash
./scripts/build.sh
```

The built app is written to:

```text
build/VibeReview.app
```

The built agent CLI is bundled in:

```text
build/VibeReview.app/Contents/MacOS/vibereview
```

Run the CLI from the repo:

```bash
./scripts/cli.sh status
```

Run the built app from the repo:

```bash
./scripts/run.sh
```

Run unit tests:

```bash
./scripts/test.sh
```

Do not run `build.sh` and `test.sh` concurrently. Both invoke XcodeGen and can race while regenerating `VibeReview.xcodeproj`.

## Install To Applications

Install the app and global CLI shim:

```bash
./scripts/install.sh
```

This writes the app to:

```text
/Applications/VibeReview.app
```

And creates or refreshes:

```text
/usr/local/bin/vibereview -> /Applications/VibeReview.app/Contents/MacOS/vibereview
```

If `/Applications` or `/usr/local/bin` requires elevated permissions, `install.sh` prompts for administrator privileges.

Use the CLI for agent-driven reviews:

```bash
vibereview start --project /path/to/game --title "Game Review"
vibereview capture --project /path/to/game --note "Jump timing feels late" --severity issue --rating 3 --tags controls,feel
vibereview end --project /path/to/game
```

## Chrome Extension

The app bundles the local extension folder into the app resources, but for browser review state capture during development, load the repo folder directly:

1. Open Chrome or another Chromium browser.
2. Go to `chrome://extensions`.
3. Enable Developer Mode.
4. Click "Load unpacked".
5. Choose `ChromeExtension`.

After editing `ChromeExtension/manifest.json`, reload the unpacked extension in `chrome://extensions`.

## Implementation Notes

- `project.yml` is the source of truth for the generated Xcode project.
- Always increment the app version when making code changes. At minimum, bump `CURRENT_PROJECT_VERSION` in `project.yml`; bump `MARKETING_VERSION` too when the change is user-visible.
- `VibeReview.xcodeproj` is generated by XcodeGen.
- App code lives under `VibeReview/`.
- Unit tests live under `VibeReviewTests/`.
- The app icon is `VibeReview/Assets.xcassets/AppIcon.appiconset`.
- Review session persistence lives in `VibeReview/Services/SessionStore.swift` and `VibeReview/Services/SessionPersistence.swift`.
- Generated user-state files under `VibeReview.xcodeproj/**/xcuserdata` should not be kept.

## Editing Guidance

- Keep changes scoped to the requested behavior.
- Prefer existing app patterns over new architecture.
- Use `rg` for search.
- Use `apply_patch` for manual file edits.
- Before handing off behavior changes, run `./scripts/test.sh` when tests are relevant and `./scripts/build.sh` when app code, project config, resources, or extension files changed.
